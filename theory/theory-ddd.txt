Чтобы следовать DDD делаем так:
1. Методы для создания сущностей делаем в виде статических методов моделей сущностей.
2. Методы для изменения и soft удаления сущностей делаем в виде методов экземпляров сущностей.
3. Методы для сохранения, поиска и hard удаления сущностей делаем в виде методов репозиториев.

/*--------------------------------------------------------------------------------------------------------------------*/

Согласно паттерну Anemic Domain Model сущности являются просто наборами данных.

Согласно паттерну Rich Domain Model сущности содержат и данные, и бизнес-логику.

Используя паттерн Rich Domain Model, в JS и TS обычно используют соглашение:
1. Классы, конструкторы и модели пишутся с большой буквы.
2. Экземпляры (конкретные объекты) пишутся с маленькой буквы.

/*--------------------------------------------------------------------------------------------------------------------*/

Aggregate root (корень агрегата) - это главная сущность в группе связанных объектов, которая является единственной
точкой входа для управления этой группой. Правила для корня агрегата:
1. Единый вход: извне нельзя менять вложенные объекты напрямую, нужно обращаться только к корню. Например, нельзя
изменить комментарий напрямую - нужно делать это через посты.
2. Целостность: корень отвечает за проверку всех правил внутри своей группы. Например, если блог заблокирован, то в нем
нельзя делать посты или оставлять комментарии.
3. Жизненный цикл: если удаляется корень, удаляются и все вложенные в него объекты. Например, если блог удаляется, то
удаляются и все посты с комментариями внутри него.

/*--------------------------------------------------------------------------------------------------------------------*/

Entity (сущность) - это объект, у которого есть уникальный ID, определяющий его.

Value Object (объект-значение) - это объект без ID, который определяется только своими значениями.

/*--------------------------------------------------------------------------------------------------------------------*/

Структурная типизация - это способ проверки типов во время компиляции кода, при котором два объекта считаются
совместимыми, если у них совпадает набор полей и методов, независимо от того, как называются их классы. TS использует
только структурную типизацию (за исключением enum). Пока пишется код, TS на фоне запускает свой компилятор и проверяет
код. В современных IDE может быть встроен TS, что позволяет использовать структурную типизацию даже для чистого JS-кода
без отдельной установки TS.

Утиная типизация - это способ проверки объектов во время выполнения кода, при котором код пытается вызвать метод или
свойство у объекта, не проверяя его тип заранее. JS использует только утиную типизацию.
